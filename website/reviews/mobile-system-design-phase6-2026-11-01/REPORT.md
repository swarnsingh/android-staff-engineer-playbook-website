# Mobile System Design Phase 6 publication review

This release completes the six-phase Mobile System Design learning path by publishing A/B Testing Infrastructure, Experimentation Platform, Server-Driven UI, and On-Device AI. All thirty-five chapter routes are now rendered locally rather than leaving the final phase linked only to GitHub. This milestone follows the separately reviewed and deployed Phase 5 release in website PR #12. It is based on that merged main branch, so its publication evidence includes the location, payment and media chapters as well as the four newly added pages.

Original playbook PR #71 was merged as 400a7d7dd85c962b6b2d6d856712ca316a11edc8, after the focused reviews of the exposure/reward ordering, loading-state and crash-quarantine changes. The four website Markdown copies are byte-identical to that source commit, with their SHA-256 hashes and phase reference recorded in source-snapshot.json. The source copy was refreshed rather than silently corrected in the website. Original sections, code, tables, questions, answers and Mermaid source remain in their original order. The normal preservation self-tests and complete chapter inventories verify that contract.

Six FigureMap models replace every Mermaid picture in these four chapters. The A/B figures distinguish assignment from actual feature exposure and keep the assignment backend separate from client evaluation. The bandit figures distinguish an immutable assignment handle from its changing allocation policy, and show exposure and rewards entering one ordered trial outbox. That outbox opens the authoritative trial; the separate best-effort analytics exposure is not its reliability mechanism. The SDUI figure keeps native rendering and allowlisted actions on the Android side and schema governance on the backend side. The AI figure places capability and policy checks before local or permitted cloud execution, with validation before a result reaches the feature.

The models use automatic layout, shared role colours and border patterns, labelled relationships and explicit ownership boundaries. Each has a numbered point-making caption and primary-source references. Local runtime, client data, queued events and external services keep distinct roles. No chapter-specific stylesheet, inline styling or shared reader component was added. The figures also expose a text transcript, so their meaning is available without following the drawn arrows or seeing colour. On narrow screens the component retains readable labels in its bounded local viewport.

A/B Testing, Experimentation and SDUI use the existing numbered interview-walkthrough layout, including its derived timeline, practice prompts and supported decision cards. On-Device AI keeps the normal layout because the source is organised around routing decisions, runtime choices, failure modes and rollout, rather than the standard twelve-section case study. Every page gets a brief introduction and a labelled interview recap. The additions reinforce the reviewed contract: explicit Loading rather than a fake control, original handles for delayed rewards, transactional exposure recording, a delivery grace policy, retained earlier-launch crash evidence, and client-enforced sensitive-data routing.

Local validation runs the build while preparing figures, then the complete build without pending figures, model checking, browser frames and the CI command. The final inventory covers 195 pages and 25,002 original units with no preservation errors. There are 156 FigureMap models across the site. Frame checks cover 189 chapter pages, 155 figures, 138 relationship maps and 3,145 labels, with no reported framing problems. The CI command passes fifteen website tests, thirty-one documentation checker tests, the documentation gate and ten browser-script syntax checks. The accompanying evidence is a new run of all six publication audits over the latest main plus this milestone; earlier Phase 5 evidence is retained as its own historical record rather than substituted for this run. The report is committed together with those JSON results and the refreshed publication fingerprint.

A focused Chromium preview at 1440 and 375 CSS pixels checked the trial-outbox, SDUI and on-device AI figures. Those pages did not create whole-page horizontal scrolling. The full audit additionally exercises the existing preference matrix, Content and Q&A preservation, enlarged text, motion behaviour, refinement, navigation and negative tampering fixtures. These are simulated browser viewports. They do not establish compatibility with every engine, real phone, screen reader or assistive-input device.

The educational code remains uncompiled as complete Android applications. Neither this release nor its browser tests execute a bandit backend, AICore device, LiteRT model or production crash pipeline. A finite trial-delivery grace period is an explicit server policy with a late-arrival limit; it is not a promise of unlimited offline delivery. SDUI quarantine protects first-frame recovery, and later lazy-section crashes still rely on crash reporting and the server kill switch. Publication is complete only after the gate passes, required PR checks pass, the PR merges, and the GitHub Pages workflow and live build provenance confirm the new deployment.
