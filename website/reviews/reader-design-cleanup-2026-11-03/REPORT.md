# Shared reader and teaching-figure cleanup

The older Kotlin and Android teaching figures used the same neutral card treatment for storage, execution and clients, and several horizontal rows relied on order to imply a relationship. This milestone migrates the complete inventory of 197 figures into shared presentation components. It preserves their existing card explanations, comparisons and timeline proportions while making relationships explicit. Original chapter files, original Mermaid sources, approved corrections and the existing Q&A experience remain unchanged.

The inventory has 75 relationship figures and 122 comparisons or timelines. Relationship models declare endpoints and labels; card order does not create arrows. Comparison and timeline figures keep their existing HTML grouping. Models supply semantic roles and sources, while the design system supplies colours, border patterns, labels, captions and geometry. The 811 original teaching cards must each have a role. A card converted to an arrow annotation retains its complete title and detail in that annotation. Every model binds to the full source figure hash. Missing, unused and stale models fail a normal build; unfinished figures are allowed only in explicitly pending local previews.

The six reader stylesheet sources moved into the ReaderShell component. Public asset paths remain stable, including relative font paths. The move preserves their original bytes; the shared StaticFigure styles are separate additions. The gallery now uses three actual lesson figures through the same parameter and timeline-label processing as the reader: backing state, stack versus heap, and initialization timing. Compact component contracts join the checker's existing exemption for short reference documents; lesson word floors are unchanged.

FigureMap can also generate a narrower phone composition using unchanged text sizes. It reflows the same semantic graph, retaining each edge and logical owner. The ordinary label, card and boundary collision checks run on the result. An alternative is emitted only if it is narrower and fits the compact token budgets; 57 maps qualify. The shared WideDiagram component selects the drawing from the width available to the figure. Marker and description IDs are distinct between alternatives. Graphs that cannot meet these conditions, and sequence diagrams whose lanes convey meaning, retain their labelled, keyboard-accessible local scrolling.

## Teaching-layer findings

- **KSP:** the legacy added card called the processing stage “Kotlin compiler,” despite the approved corrected chapter explicitly distinguishing KSP2 from a Kotlin compiler plugin. The added card now names standalone KSP2 source analysis, with a caption separating processing from final compilation. The source chapter and original Mermaid source are untouched. Primary evidence: [KSP2 execution model](https://github.com/google/ksp/blob/main/docs/ksp2.md), including its independent entry point and Gradle-daemon execution.
- **Activity launch:** the legacy added card named ActivityManagerService as the direct `startActivity` coordinator. The current AOSP activity/task service exposes that entry point, so the added card now names ActivityTaskManagerService and retains package resolution as a distinct responsibility. Primary evidence: [AOSP ActivityTaskManagerService](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/services/core/java/com/android/server/wm/ActivityTaskManagerService.java). The original chapter's AMS schematic remains preserved. Its version-specific naming is recorded here for a later source review; no unapproved replacement is applied to that original text or diagram.


## Validation and limits

A comparison with the current main renderer also confirms that all 220 existing desktop SVGs remain byte-identical after removing the new variant attribute. The first complete build preserved 249 pages and 30,397 original content units in their existing order. Model checks cover all 220 original redraws plus the 197 teaching models. New regressions exercise source drift, missing roles, dropped cards, annotations, nested comparison structure, unused models and distinct compact SVG identifiers. The desktop browser frame sweep covers all 238 chapter pages; it now also checks the comparison cards and their visible frames. The phone sweep distinguishes a labelled local scroll boundary from page overflow instead of treating any wide drawing as a failure.

The initial representative gallery inspection exposed a missing parameter/timeline transformation in the new gallery samples and an undersized gallery frame. Both were corrected in the shared gallery path before final verification. Existing lesson rendering already applied those transformations. The first full audit then rejected two Coroutines timeline numbers at 320px with enlarged text: inherited mobile padding consumed their interior width. Removing padding from numbered StaticFigure marks preserves bar proportions and text size. That failed run is retained in `attempts/01-enlarged-timeline/`; the final audit is run against the corrected source. Retained [gallery evidence](gallery.json) and screenshots cover the three figure forms in light, dark, sepia and high-contrast themes on desktop. Mobile checks for this milestone are automated. The consolidated full manual mobile review remains deferred until all planned trees and pages are implemented, following the owner's review-timing rule.

This milestone does not finish every reader backlog item. Some legacy routing, sequence and ReaderShell dimensions still need tokens. Complex graphs retain local scrolling. A rough inventory of added prose flags 31 of 221 chapters above the quarter-length working target, including two cross-reference stubs; those ratios require editorial review before any trimming. Practice mode stays unchanged, with no new prediction or decision exercise mode. These limits remain recorded in AGENTS.md rather than being presented as completed work.
