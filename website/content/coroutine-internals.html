A value must survive the next suspension.

In the sequential teaching example below, the name is fetched first. It is still needed after the avatar request suspends. The generated state therefore needs to retain it. This example explains lowering; the earlier concurrent example has a different execution policy.

Saved locals across two callsKotlin fragment · api and Profile supplied by the app
suspend fun assembleProfile(): Profile {
    val name = api.fetchName()
    val avatar = api.fetchAvatar()
    return Profile(name, avatar)
}
One possible state-machine shape; label values and field names are explanatory.
PositionSaved stateNext action
Label 0: entryCaller’s completionSet next label to 1, then call fetchName with this function’s state continuation.
Label 1: name availableName, caller’s completionKeep name in a field, set next label to 2, then call fetchAvatar.
Label 2: avatar availableRestored name, avatar resultConstruct Profile. Deliver it to the suspended caller through the completion chain.

Before either call, the continuation records where to resume. If the call returns immediately, execution continues with that value. If it returns COROUTINE_SUSPENDED, the function returns the marker instead of holding the thread’s stack through the wait. A later resume supplies a result or a failure.

The function’s state continuation retains its caller’s completion continuation. Finishing after resumption delivers a result through that chain; it does not return into an old OS stack frame that has been kept waiting. JVM BaseContinuationImpl.resumeWith can loop through compatible continuation frames rather than recursively calling each one. The dispatcher’s continuation interception determines where scheduled resumption executes.
