Two ways to make the avatar optional

The profile can still be useful without an avatar. Decide whether the child exposes a normal nullable result or a failed Deferred. Those are different contracts.

Convert expected failure inside the childKotlin fragment · main-safe api; nullable Profile.avatar
suspend fun loadProfile(): Profile = coroutineScope {
    val name = async { api.fetchName() }
    val avatar = async {
        try {
            withTimeoutOrNull(1_000) { api.fetchAvatar() }
        } catch (error: IOException) {
            null
        }
    }
    Profile(name.await(), avatar.await())
}

The expected avatar failure becomes null before the child completes. The child therefore completes normally, so this policy works with an ordinary coroutineScope. The narrow IOException catch does not catch CancellationException. Unexpected failures still fail the group.

Let the child fail; handle its result under supervisionKotlin fragment · same api and Profile assumptions
suspend fun loadProfile(): Profile = supervisorScope {
    val name = async { api.fetchName() }
    val avatar = async {
        withTimeoutOrNull(1_000) { api.fetchAvatar() }
    }
    val resolvedName = name.await()
    val resolvedAvatar = try {
        avatar.await()
    } catch (error: IOException) {
        null
    }
    Profile(resolvedName, resolvedAvatar)
}

Here an IOException actually fails the avatar child. The supervisor keeps the name child active. The caller later converts that failed Deferred to a placeholder. With an ordinary parent, the failed avatar would already have cancelled the group; catching only around await cannot undo that cancellation.

If name fails, its awaited exception escapes the scope block and fails the load. If the owner cancels, cancellation still reaches both children. A timeout covers only its own cooperative block and is not a hard interruption deadline. Neither supervision nor a timeout turns an unhandled failure into UI state; the outer launch boundary shown with the animation performs that conversion.
