Start with the problem

You rotate while products are loading.

If the Activity owns the loading state directly, its replacement starts without that in-memory state. A naive onCreate() implementation can launch the request again.

Assumptions and official sources
  • Standard Activity recreation on rotation; no custom configuration-change handling. The same owner scope and ViewModel key are used.
  • The example starts one loading job in VM1. Retaining VM1 preserves that job's lifetime; application code must still avoid launching duplicate work.
  • Boundaries show logical ownership, not physical memory allocation. The middle rotation state simplifies Android's non-configuration retention.
  • Cleared objects can remain in memory if other references exist. Clearing is distinct from garbage collection.
